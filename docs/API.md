# Cantarella API

This document describes the current V1 HTTP and real-time event surface. See the [root README](../README.md) for setup and [Architecture](ARCHITECTURE.md) for internal execution details.

## Conventions

The health check is public. Every `/api/v1` endpoint requires an Auth0 bearer token:

```http
Authorization: Bearer <access-token>
```

Successful responses use a `data` envelope:

```json
{
  "data": {}
}
```

Errors use:

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable description",
    "retryable": false
  }
}
```

Public identifiers are UUIDs. JSON request bodies are validated strictly, so unknown fields may be rejected.

## Health

### `GET /ping`

Returns API health without authentication.

```json
{
  "data": {
    "status": "ok"
  }
}
```

## Account

### `POST /api/v1/auth/login`

Bootstraps or loads the authenticated account. Despite its name, browser authentication happens through Auth0; this endpoint synchronizes the validated identity with Cantarella's database.

For a first-time identity, the backend creates default settings, persona, and primary conversation atomically.

The response includes:

- account ID, name, and email
- timezone
- primary conversation ID
- onboarding state
- current persona configuration
- `isNewUser`
- `onboardingRequired`

### `GET /api/v1/me`

Returns the current account snapshot after bootstrap.

### `PUT /api/v1/onboarding`

Completes initial onboarding. The accepted object contains the user's timezone and persona configuration as defined by the current onboarding schema.

The persona supports:

- name
- preferred user name
- one voice direction
- optional custom style additions
- endearment preference
- explicit boundaries

### `PUT /api/v1/settings`

Updates account settings and persona additions. Persona edits create a new persona version for model-run traceability.

## Conversation

### `GET /api/v1/conversations/primary`

Returns the authenticated user's one Cantarella conversation.

```json
{
  "data": {
    "id": "7a341fce-6ca1-46dd-9efd-5737408f7971",
    "title": "Cantarella",
    "lastMessageAt": "2026-08-13T09:00:00.000Z",
    "unreadCount": 0
  }
}
```

### `GET /api/v1/conversations/:conversationId/messages`

Returns cursor-paginated history owned by the authenticated user.

Query parameters:

| Name | Type | Default | Notes |
| --- | --- | --- | --- |
| `before` | UUID | omitted | Message ID used as an exclusive older-history cursor |
| `limit` | integer | `50` | Minimum 1, maximum 100 |

Response:

```json
{
  "data": {
    "messages": [],
    "nextCursor": null,
    "hasMore": false
  }
}
```

A message snapshot contains:

```json
{
  "id": "d05d0281-7722-4852-9c9c-d25e6f6f005d",
  "turnId": "f4874b93-41ed-412f-919a-6176eea8854a",
  "clientMessageId": null,
  "sender": "assistant",
  "content": "message text",
  "messageKind": "chat",
  "source": "system",
  "partIndex": 0,
  "status": "delivered",
  "replyToMessageId": null,
  "createdAt": "2026-08-13T09:00:00.000Z"
}
```

Message status is one of `sent`, `seen`, `delivered`, or `failed`.

### `POST /api/v1/conversations/:conversationId/messages`

Idempotently accepts one user bubble and schedules its turn.

```json
{
  "clientMessageId": "80b96dd7-f14f-4f3d-aa09-ed8598f911d1",
  "content": "remind me at 9 tonight to check the mailbox",
  "source": "web",
  "replyToMessageId": null
}
```

Constraints:

- `clientMessageId` must be a UUID generated by the client
- `content` must contain 1–10,000 trimmed characters
- `source` is `web`, `android`, or `ios`
- quoted replies are not implemented, so `replyToMessageId` is currently null

The endpoint returns `202 Accepted` after durable storage:

```json
{
  "data": {
    "message": {},
    "turn": {
      "id": "f4874b93-41ed-412f-919a-6176eea8854a",
      "status": "queued"
    }
  }
}
```

The same `clientMessageId` and same payload return the existing assignment. Reusing it for different content produces `CLIENT_MESSAGE_ID_REUSED`.

## Conversation events

### `GET /api/v1/conversations/:conversationId/events`

Opens an authenticated Server-Sent Events stream. Response headers disable buffering and caching. A comment heartbeat is sent every 15 seconds to keep the stream alive.

Each event has the standard form:

```text
event: message.created
data: {"message":{...}}
```

### `connected`

Emitted after the stream is established.

```json
{
  "conversationId": "7a341fce-6ca1-46dd-9efd-5737408f7971"
}
```

### `turn.status`

Reports processing movement used for seen state and UI feedback.

```json
{
  "turnId": "f4874b93-41ed-412f-919a-6176eea8854a",
  "status": "thinking"
}
```

Streamed states are `thinking` and `voicing`.

### `typing.started` / `typing.stopped`

```json
{
  "conversationId": "7a341fce-6ca1-46dd-9efd-5737408f7971",
  "sender": "assistant"
}
```

### `message.created`

Emitted once for each stored assistant or reminder bubble.

```json
{
  "message": {}
}
```

### `turn.completed`

```json
{
  "turnId": "f4874b93-41ed-412f-919a-6176eea8854a"
}
```

### `turn.failed`

```json
{
  "turnId": "f4874b93-41ed-412f-919a-6176eea8854a",
  "code": "OpenRouterError",
  "message": "Cantarella couldn't respond.",
  "retryable": false
}
```

The user message remains in history and should be rendered with a visible failed state.

## Memories

### `GET /api/v1/memories`

Lists memories owned by the authenticated user.

Supported filters are defined by the request schema and include status, type, substring search, and limit.

Response:

```json
{
  "data": {
    "memories": []
  }
}
```

Memory snapshots expose:

- ID
- type
- canonical content
- importance and confidence
- status
- expiry
- reinforcement, creation, and update timestamps

### `POST /api/v1/memories`

Creates a user-confirmed manual memory. The request includes:

- `content`
- `type`
- `importance`
- `expiresAt`

Situation memories require a future expiry. Duplicate normalized active memories return `MEMORY_ALREADY_EXISTS`.

### `PATCH /api/v1/memories/:memoryId`

Updates one owned active memory. Fields are partial, and unchanged fields preserve their current values. Content changes create a new current embedding while retaining valid embedding history.

### `DELETE /api/v1/memories/:memoryId`

Permanently deletes the selected memory lineage and its cascading evidence and embedding records.

## Reminders

### `GET /api/v1/reminders`

Lists reminders owned by the authenticated user. Query filters include status and limit.

```json
{
  "data": {
    "reminders": []
  }
}
```

### `POST /api/v1/reminders`

Creates a manual reminder. The input supports title, local schedule, timezone-aware recurrence, and the fields defined by the current reminder schema.

### `PATCH /api/v1/reminders/:reminderId`

Updates the content, schedule, recurrence, or state of one owned reminder.

### `DELETE /api/v1/reminders/:reminderId`

Permanently removes a reminder. This is distinct from setting its state to cancelled.

## Common errors

| Code | Meaning |
| --- | --- |
| `UNAUTHORIZED` | Missing or invalid authenticated identity |
| `ACCOUNT_NOT_INITIALIZED` | Login bootstrap has not created the local account |
| `CONVERSATION_NOT_FOUND` | Conversation does not exist or is not owned by the user |
| `INVALID_MESSAGE` | Message body violates its schema |
| `INVALID_MESSAGE_CURSOR` | History cursor does not belong to the conversation |
| `CLIENT_MESSAGE_ID_REUSED` | Idempotency key was reused for different content |
| `MEMORY_NOT_FOUND` | Memory does not exist or is not owned and active |
| `MEMORY_ALREADY_EXISTS` | Equivalent active canonical memory already exists |
| `REMINDER_NOT_FOUND` | Reminder does not exist or is not owned by the user |

Exact status codes and additional validation errors are defined alongside their route modules under `backend/src/api/`.
